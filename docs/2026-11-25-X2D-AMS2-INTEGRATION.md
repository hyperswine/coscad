# X2D and AMS 2 Pro arrival notes

The installed Bambu Studio 02.08.02.61 already includes X2D machine ID N6, paired 0.4 mm nozzle definitions (direct drive and Bowden), and X2D filament presets for PETG HF, both PLA support products, TPU grades and PETG-CF. Profile inspection is local evidence. Device firmware, live LAN control, camera, actual routing and print outcomes await the delivered machine.

## Material routing with one AMS

Use the upper buffer inlet to assign the AMS to the left/main nozzle and load an external support spool for the right/auxiliary nozzle. The lower inlet assigns the AMS to the auxiliary instead. Record which arrangement the owner actually installed. A Filament Track Switch is a separate configuration; its routes and TPU behavior require their own verification. [X2D manual, sections 2.2, 6.2 and 7.3](https://csm.bblcdn.com/hub/7c58718aaa2e40edab56efb87419a96a.pdf) · [Bambu's TPU and track-switch explanation](https://github.com/bambulab/BambuStudio/issues/12199)

| Job | First configuration to qualify |
|---|---|
| PETG | PETG on the main nozzle from a recorded AMS slot. Confirm a single-filament package and the live feed source. |
| PETG with release interface | PETG for the part and support base. Assign **Support for PLA/PETG** to Support/Raft Interface on the auxiliary nozzle. Verify the support SKU at loading. Studio also ships a different **Support for PLA** preset. Ordinary PLA as a PETG interface is a separate material-pair experiment. |
| Soft TPU, including ordinary 95A | External spool to main direct drive with the flexible-filament path configured per the X2D guide. Keep this distinct from the stiffer product labeled **TPU for AMS**. |
| PETG-CF | Bambu PETG-CF is listed for AMS 2 Pro. Use the main nozzle, hardened steel and the exact filament profile. Bambu supports 0.4 mm and recommends 0.6 mm for lower clog risk. Verify third-party CF formulations separately. |

Sources for those pairings and restrictions are the [AMS 2 Pro spec sheet](https://store.bblcdn.com/s3/default/02bc9c24b207476a9608a314b8039509/AMS_2_Pro-EN.pdf), [X2D extrusion guide](https://blog.bambulab.com/two-extruders-one-purpose-what-is-x2d-direct-drive-extrusion-and-auxiliary-extrusion/), [support product guide](https://bambulab-us.myshopify.com/products/support-for-pla-petg) and [PETG-CF product guide](https://bambulab-us.myshopify.com/products/petg-cf).

## CoScad package preparation and dispatch

- Extend the printer table in scripts/verify-prepared.sol with N6. scripts/slice-prepared.sol currently passes one filament preset per prepared job. Preserve ordered model/support profiles, physical nozzle assignments and the AMS/external source for each filament in the job record. Reconcile the package with the connected topology before sending it.
- Inspect a Studio-exported dual-material package offline. Check nozzle diameters, body versus interface toolpaths, temperatures per tool, prime tower and footprint. Main-only reach is 256 × 256 × 260 mm. Shared reach is 235.5 × 256 × 256 mm; Studio marks the strip on the left reserved for the main tool. Re-slice large diagonal plates for the selected configuration.
- Existing dispatch records use a printer URL on /sdcard and a flat AMS mapping or external spool. The X2D manual describes USB storage. Verify the actual upload, readback and project-file location on this firmware before adopting a URL convention. Start with Studio on the LAN. For direct third-party control the X2D manual documents LAN Only then Developer Mode; LAN Only gives up Handy/cloud access. Test telemetry and command acceptance separately. Keep single-send dispatch and reconcile uncertain acknowledgements from status.
- Studio carries both source identity and extruder direction. The physical slot label alone cannot select a nozzle. Match the Studio release and capture a sanitized known-good job before choosing the wire encoding. [Studio nozzle mapping](https://github.com/bambulab/BambuStudio/blob/master/src/slic3r/GUI/DeviceCore/DevMappingNozzle.cpp) · [X2D user manual](https://csm.bblcdn.com/hub/7c58718aaa2e40edab56efb87419a96a.pdf)

## AMS telemetry and 3dprint.cswine.cloud

The documented implementation path is through the printer. Studio parses AMS reports and sends dryer commands to the printer identified by its device session. No standalone supported LAN REST service for the AMS was identified in the reviewed material. Treat Studio source as firmware-dependent implementation evidence.

- Store each AMS unit and tray by reported ID. Keep the external feed and nozzle assignment explicit. Studio parses humidity level and percent separately (humidity and humidity_raw), temperature, remaining drying time, state, settings and reasons drying is unavailable where supported. Preserve missing fields across deltas; after reconnect obtain a fresh full report. A missing percent must not be displayed as zero. [Studio AMS parser](https://github.com/bambulab/BambuStudio/blob/master/src/slic3r/GUI/DeviceCore/DevFilaSystem.cpp)
- Studio uses ams_filament_drying for start/stop with a target AMS, mode and, where supported, zone and settings. A read-only dashboard can display drying without implementing a heater control. Simultaneous drying depends on firmware, power and setup; verify eligibility in Studio. [Studio dryer implementation](https://github.com/bambulab/BambuStudio/blob/master/src/slic3r/GUI/DeviceCore/DevDryer.cpp) · [X2D firmware announcement](https://forum.bambulab.com/t/first-update-for-x2d-is-out-ota-01-01-00-00/250867)
- The printer repository's src/printer-telemetry.fpr already subscribes to the printer report, requests pushall and delegates decoding to std/printertelemetry. The upstream dashboard projection in fprisc/examples/printer-dashboard/printertelemetry.fpr exposes a single nozzle and filament source. Extend the decoder and authenticated UI together; retain legacy scalar fields for A1/P1S/X1C. Register the X2D by verified serial, host and TLS identity. Check the running host's version before choosing the deployment checkout. Camera support is a separate acceptance item: identify the actual supported stream and verify two fresh images through the authenticated site before enabling it.
- Arrival sequence: record firmware, nozzle inventory and feed routing; run the printer's own calibrations, including the nozzle-to-nozzle offset if the X2D has one (expected on a two-nozzle printer; confirm in the manual), before any interface coupon; compare live full and incremental reports with the touchscreen; qualify a main-only PETG print; qualify a PETG/interface coupon with a real tool change and clean peel; then test external TPU and PETG-CF independently. Verify source selection, temperatures and tool changes at the printer and through the dashboard. Finish by checking that the other three printers still report normally.

## Additions after the A1 AMS Lite test, 2026-11-25

A three-colour AMS Lite test on the A1 (`models/ams-tricolor-test/a1`) exercised the current dispatch path before the X2D arrives. What it showed, and what follows for the X2D:

- **Flat mapping works as a baseline.** `project_file` with `use_ams: true` and `ams_mapping: [0, 1, 2]` was accepted for a three-filament package sliced with `--load-filaments` and `--load-filament-ids "1,2,3"`. Expect the X2D to need more than tray indices to choose a nozzle. Do not hand-build a multi-nozzle dispatch until a Studio-sent job has been captured and compared.
- **Feed faults must stop dispatch, not just appear in logs.** The test paused at the first load with `print_error` 0x12008006 and `HMS_1200_1000_0002_0002` (AMS Lite feeder motor overload: filament stuck or the path too stiff; [wiki](https://wiki.bambulab.com/zh/a1-mini/troubleshooting/hmscode/1200_1000_0002_0002)). Dispatch scripts should decode `print_error` and `hms` while they watch the startup, report the fault and the target tray (`tray_tar`), and never resume on their own. HMS module prefixes differ by AMS model (`1200` for the AMS Lite); record the AMS 2 Pro and X2D prefixes from the first real fault or the HMS wiki before writing a decoder table. The printer dashboard already tracks `hms_reported` and `print_error_reported` (`printer/src/printers.fpr`), so extend that rather than adding a second decoder.
- **Cancel is a tested command.** `{"print": {"command": "stop"}}` cancelled the paused A1 job (state FAILED, `print_error` 0x0300400C). Verify the same on the X2D during qualification, once, while the job is in a known state.
- **Check the trays before sending.** The A1 dispatcher refuses to start unless each mapped tray reports the expected `tray_type` and colour. Make this a rule for the X2D, per nozzle as well as per tray. Also compare the sliced filament ID with the loaded spool's `tray_info_idx`. The test package carried `GFA00` while the trays reported `GFSNL04`, `GFL99` and `GFSNL03`. That is harmless for PLA but matters for PETG-CF, TPU for AMS and the support products.
- **Extend the thermal preflight to two tools.** Earlier A1 records carry `coscad.thermal-preflight/1` (expected plate, bed and nozzle temperatures checked against the toolpath). Extend it to each tool's temperatures, including the standby temperature of the idle nozzle.
- **Nozzle inventory.** Installed Studio ships X2D machine profiles for 0.2, 0.4, 0.6 and 0.8 mm nozzles, not 0.4 mm only. Record which nozzles are on hand, and which are hardened steel, before choosing PETG-CF settings (0.6 mm is recommended above).
- **Network identity.** The P1S's address moved from 192.168.0.28 to .27, and the A1 serial was missing from `3d-models/.env`. Both were corrected on 2026-11-25 from `bambu-lan/discover.py`, which listens about 70 seconds; the A1 broadcasts less often than the others. Before the X2D arrives, give each printer a DHCP reservation. Take the X2D's serial and advertised model code from discovery rather than assuming `N6`, and add `BAMBU_X2D_HOST`, `BAMBU_X2D_SERIAL` and `BAMBU_X2D_ACCESS_CODE` to `.env`.
